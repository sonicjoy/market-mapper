# Bootstrap NCAAB Team Aliases

## Usage

```
python -m scripts.bootstrap_ncaab_aliases data/ncaab/2026-02-21 data/ncaab/2026-02-25
```

Positional arguments: one or more data directory paths. Overwrites
`config/ncaab/team_aliases.toml` in place. Progress/diagnostics to
stderr, game-by-game matching report to stdout.

## Results (from 2 dates of data)

| Metric | PX | Kalshi |
|--------|---:|-------:|
| Unique abbreviations seen | 323 | 357 |
| Identity matches (comment-only) | 110 | 285 |
| Non-identity aliases (TOML sections) | 213 | 58 |
| Unresolved (no Optic game in data) | 0 | 14 |

All 323 PX abbreviations resolved. 14 Kalshi codes (Akron, Brown,
Bryant, etc.) had no matching Optic game in either date — they'll
resolve when data directories covering those games are added.

## Data quirks discovered

### PX abbreviation collisions

PX reuses the same abbreviation for different teams:

- **`COL`** = Columbia Lions (1 game) AND Colorado Buffaloes (2 games).
  Script picks the majority mapping (`COL → COLO`). The one Columbia
  game (`DART @ COL`) will fail in the pipeline.

- **`CSU`** = Cal State Bakersfield (PX name "Bakersfield Roadrunners")
  — but Optic's `CSU` is Colorado State. The identity seed `CSU = CSU`
  was wrong. The script detects this via propagation conflict and
  remaps `CSU → CSUB`.

### Kalshi GAME-type market gaps

~3 Kalshi game groups lack GAME-type (moneyline) markets, having only
SPREAD/TOTAL. `resolve_game()` raises `ValueError` for these because
`_disambiguate_teams` requires exactly 2 GAME market suffixes. The
script catches and skips them.

### Kalshi date misalignment

~2 games have Kalshi dates off by 1 day from the ET date (e.g.
Wake@BC coded as Feb 24 but is actually Feb 25 ET). These fall
through as unmatched in their wrong-date slot but get resolved
via name matching or process of elimination in a neighboring slot.

### Kalshi market deduplication

The same game appears in multiple snapshot directories (e.g. a
Feb 25 game exists in both the Feb 21 and Feb 25 snapshots). Markets
are deduplicated by ticker to avoid `_disambiguate_teams` seeing 4
GAME suffixes instead of 2.

### Identity seed validation

Identity seeding (PX abbr == Optic abbr → assume same team) is
mostly correct but can be wrong (see CSU above). When propagation
discovers a conflicting mapping for an identity-seeded abbreviation,
it overrides the identity with the propagation-derived mapping on the
grounds that slot-level game matching is stronger evidence than
abbreviation coincidence.

### Slot sizes and performance

The Feb 21 date has 148 Kalshi games in a single date slot.
Propagation uses set-based lookups (optic pairs as a set, optic
games indexed by abbreviation) to keep matching O(n) per pass
rather than O(n²).

## Algorithm overview

Three phases, each running for both PX and Kalshi. PX matches by
UTC timestamp (exact), Kalshi matches by ET calendar date.

1. **Constraint propagation** — seed from identity matches, then
   iterate: full match → partial match → force match (1:1 remaining).
2. **Name matching** — for stuck slots, normalized Optic name must
   be a prefix of exchange name. Re-run propagation afterward.
3. **Verification** — scan for resolved-but-unmatched games (both
   teams have aliases but the game doesn't match any Optic game).
   Indicates a wrong alias; remap to the majority candidate.

After all phases, unresolved abbreviations and conflicts are
reported to stderr.

## TOML output format

Alphabetical by canonical (Optic) abbreviation. Identity matches
are comments; non-identity aliases are sections:

```toml
# NCAAB team aliases: canonical (Optic) → exchange variants.
# Generated by scripts/bootstrap_ncaab_aliases.py

# ARMY = ARMY  (Army ← PX: Army Black Knights, Kalshi: Army)

# Charlotte ← Charlotte 49ers (PX), CHAR (Kalshi)
[CLT]
px = ["CHARLT"]
kalshi = ["CHAR"]

# RID = RID  (Rider ← Kalshi: Rider)
```

An identity comment listing both `PX:` and `Kalshi:` means all
three sources agree. One exchange only means the other didn't have
a game involving that team in the data.

## Verification

1. Run script, review report for obviously wrong pairings
2. `python -m mappers.run ncaab data/ncaab/2026-02-21 --json | wc -l`
3. `python -m mappers.run ncaab data/ncaab/2026-02-25 --json | wc -l`
4. `mise test && mise check`

Steps 2–3 currently crash on the Kalshi GAME-type gap (pipeline
issue, not alias issue) and on the COL collision (1 PX game).

## PX abbreviation collision: design problem and WIP solution

### The problem

PX reuses abbreviations for different teams. `COL` means both
Columbia Lions (competitor id `60000159`) and Colorado Buffaloes
(competitor id `60000250`). The current alias system is a flat
`dict[str, str]` (abbreviation → canonical), so it can only map
`COL` to one team. The loser's games crash the pipeline.

This is not a theoretical risk — it happens in our NCAAB data
today (Columbia's `DART @ COL` game fails). And if Columbia ever
played Colorado, PX would have two competitors both with
abbreviation `COL`, making the game completely unresolvable from
abbreviation alone.

### Why abbreviation is the wrong key

The PX abbreviation does NOT appear in PX market shapes at all.
Markets reference teams by `competitor_id` (an integer) and
`display_name` / `name` (a string). The abbreviation only appears
in the event's `competitors` array alongside the id and name:

```json
{"competitors": [
  {"abbreviation": "COL", "id": 60000159, "name": "Columbia Lions", "side": "home"},
  {"abbreviation": "DART", "id": 60000165, "name": "Dartmouth Big Green", "side": "away"}
]}
```

So the id and name are the stable, unambiguous identifiers. The
abbreviation is just a display convenience that PX doesn't even
use consistently.

### Where abbreviation is used in the pipeline (4 touch points)

1. **`px.py:_sides()`** — resolves `comp.abbreviation` →
   canonical to build the `MatchKey`. Has full access to
   `Competitor` (id, name, abbreviation, side).

2. **`px.py:build_comp_map()`** — builds
   `{competitor_id: canonical_abbrev}` for side-label resolution.
   Same access to full Competitor.

3. **`px.py:extract_team()`** — parses the market name string
   `"COL: Team Total Points"` → `"COL"` → alias lookup. Only has
   the string, no competitor info. This is the hard one.

4. **`px.py:classify_and_enrich()`** — calls `extract_team`.
   Currently receives the global alias dict, no event context.

For points 1 and 2, disambiguation is easy — the Competitor object
carries id and name. For point 3, the market name only contains
the abbreviation, so disambiguation requires knowing which event
the market belongs to (which is known upstream).

### WIP implementation (partially committed, needs review)

The current WIP adds collision support to the alias system:

**New types in `mappers/shared.py`:**
- `CollisionEntry(canonical, id, name)` — one candidate for an
  ambiguous abbreviation.
- `AliasValue = str | list[CollisionEntry]` — union type.
- `AliasMap = dict[str, AliasValue]` — the alias dict type.
- `resolve_team(abbr, aliases, name=None, competitor_id=None)` —
  fast path for simple aliases, name-match + id-check for
  collisions.
- `simple_alias_map(alias_map)` — extracts `dict[str, str]` for
  player aliases (which never have collisions).

**Changes in `mappers/exchanges/px.py`:**
- `_sides()` and `build_comp_map()` signatures changed from
  `dict[str, str]` to `Mapping[str, AliasValue]`, now call
  `resolve_team(comp.abbreviation, aliases, comp.name, comp.id)`.
- `classify_and_enrich()` signature changed: parameter renamed
  from `team_aliases` to `event_team_map: dict[str, str]` — a
  pre-resolved per-event map with no ambiguity.
- `extract_team()` unchanged — still receives `dict[str, str]`,
  but now that dict is per-event rather than global.

**Changes in `mappers/pipeline.py`:**
- After parsing each PX event, builds a per-event resolved map:
  `{comp.abbreviation: resolve_team(...)}` stored in
  `event_team_maps: dict[int, dict[str, str]]`.
- Passes `event_team_maps[sport_event_id]` to
  `classify_and_enrich` instead of the global alias table.
- Kalshi alias lookups changed from `.get(away, away)` to
  `resolve_team(away, kalshi_team_aliases)`.

**Proposed TOML format for collisions:**
```toml
[COLO]
px = [{abbr = "COL", id = 60000250, name = "Colorado Buffaloes"}]

[COLU]
px = [{abbr = "COL", id = 60000159, name = "Columbia Lions"}]
```

**Tests in `tests/mappers/test_team_abbrev.py`:**
- `test_load_aliases_collision_entries` — table entries produce
  `list[CollisionEntry]`.
- `test_resolve_team_*` — simple, identity, collision+name,
  collision+no name (raises), wrong name (raises), id mismatch
  (asserts).

**Status:** shared.py, px.py, pipeline.py, and tests are done and
passing (`mise test && mise check` clean). The bootstrap script
(`scripts/bootstrap_ncaab_aliases.py`) changes are incomplete —
`write_toml` collision entry emission is WIP and too complex.

### Concern: complexity

The `AliasValue = str | list[CollisionEntry]` union type adds
branching throughout the alias system. `write_toml` in the
bootstrap script becomes especially messy because it needs to
figure out which name/id goes with which canonical for each
conflict candidate.

### Alternative approach to consider: competitor id dict

Instead of the collision-aware alias system, maintain a separate
`dict[int, str]` mapping PX `competitor.id` → canonical
abbreviation. This would be:

- **Verbose** — every PX team needs an entry (not just
  non-identity aliases), since competitor ids aren't predictable.
- **Unambiguous** — no collision possible, ids are globally unique.
- **Simple** — no union types, no `resolve_team`, no collision
  detection in `write_toml`. Just a flat dict lookup.
- **Fragile?** — if PX ever changes a competitor id, the entry
  breaks. But abbreviations can change too.

The TOML would look something like:
```toml
[COLO]
px_id = 60000250

[COLU]
px_id = 60000159

[GSW]
px_id = 60000042
```

Or as a separate file (`config/ncaab/px_competitor_ids.toml`)
to avoid mixing with the abbreviation-based aliases.

The pipeline would look up by `comp.id` first; if found, use the
canonical. If not found, fall back to abbreviation-based lookup
(or crash — fail-fast on unknown teams).

`extract_team()` would still need the per-event resolution
approach (market names contain abbreviations, not ids), but the
per-event map would be built from id lookup instead of
collision-aware alias resolution.

The bootstrap script would just emit `{id: canonical}` pairs for
every team it sees — no conflict detection needed in the TOML
output phase.
